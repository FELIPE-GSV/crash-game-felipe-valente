# Crash Game — Design System (MASTER)

Generated by **UI/UX Pro Max** workflow.
Source of truth for visual decisions across the frontend. Page-specific overrides live in `design-system/pages/<page>.md`.

> Inspired by reference shots:
> - PikaCrash — Real-Time Casino Crash Game Interface
> - Crash Game Casino Dashboard UI/UX (Web/Mobile)
> - Casino Crash Game Animation
>
> Synthesis: a content-first **immersive entertainment** product type, **glassmorphism on neon dark mode** style, with **rocket-driven** spatial feedback as the core gamified loop.

---

## 1. Pattern & Style

| Decision | Value | Why |
|---|---|---|
| Product type | Entertainment / Gaming (real-time betting) | Action loop is short (10s bet → flight → cashout); needs constant motion feedback. |
| Style | Neon glassmorphism + dark mode | Matches casino premium tone; glass surfaces let the trajectory + starfield read through. |
| Hierarchy | Stage-first (multiplier dominates), bet panel secondary, history tertiary | Reference shots all keep the multiplier 60–70% of the optical center. |
| Motion language | Spring/physics, exit faster than enter, no decoration-only animation | `--ease-spring` + `--duration-*` tokens. |
| Icon family | Lucide / inline SVG (no emoji) | Tiers + actions need stroke consistency. |

## 5. Motion Principles (gamified)

1. **The rocket is the multiplier.** Position, scale, glow, and trail length all derive from the live `multiplier` value.
2. **Trajectory is a curve, not a line.** Use `cubic-bezier(0.16, 1, 0.3, 1)` so growth feels exponential.
3. **Crash = explosion.** Rocket flies offscreen on crash, multiplier turns red and shakes (existing `crash-shake`), background flashes red overlay (existing `crashOverlay`), then settles.
4. **Particles & stars.** Subtle background starfield (parallax 2 layers). Activated only when status === `running`. Disabled under `prefers-reduced-motion`.
5. **Exit < Enter.** Cashout pop, gain popup: enter ~280ms (spring), exit ~180ms.
6. **Tap response < 100ms.** Button press scale `0.97`, `transform`-only.

## 6. Spatial Layout

Reference shots align on:
- **Hero stage**: 16:9-ish ratio for multiplier+rocket trajectory, full-bleed on mobile.
- **History strip**: horizontal pills above the stage (last 10–20 rounds with tier colors).
- **Bet panel**: split or stacked below the stage; primary CTA is the largest hit target on screen.
- **Side rail (desktop only ≥1024px)**: history list, current bets feed.

## 7. UX Guardrails (from `ux` domain)

- `touch-target-size`: bet/cashout button ≥ 56px on mobile.
- `loading-buttons`: disable + spinner while `placeBet` / `cashout` resolves.
- `reduced-motion`: starfield, rocket trail, glow pulses all opt-out via media query.
- `aria-live="polite"`: live multiplier value, gain popup, crash announcement.
- `color-not-only`: tier always paired with rocket-icon + text. Crash uses both red + shake + skull/burst icon.
- `focus-states`: 2px ring on `--color-primary` for keyboard nav.
- `tabular-nums`: every numeric (multiplier, balance, history) uses tabular figures to prevent layout jitter.

---

## 8. Anti-patterns

- ❌ Animating `width`/`height`/`top`/`left` for the rocket → use `transform: translate3d`.
- ❌ Repainting starfield each frame on the main thread → use a single CSS keyframe + `will-change: transform`.
- ❌ Hover-only affordances on cashout button (mobile primary).
- ❌ Crash announced by color alone (must include label "CRASHED" + shake + icon).
- ❌ Rocket as decorative emoji (use SVG, scales cleanly).
